# 分析対象プロダクト「NIGHTOS」の仕様（これが事実ベース）

NIGHTOS は、日本の夜の店（キャバクラ・クラブ・ラウンジ）向けの **顧客関係管理 + キャスト育成 + AI 接客アシスタント** を1つにした業務プラットフォーム（Web アプリ）。コアの設計思想は **「店舗が入力 → ママ/お姉さんが育成 → キャストが活用」** という、これまで分断されていたデータフローを一気通貫でつなぐこと。中心的に解こうとしている課題は **「一度きりの来店を、継続的な関係（リピート・指名・同伴）に変える」** こと。

## 業態の違い（プロダクトが切り替えて対応）
- **クラブ（club）**: 担当制。同伴と継続来店が鍵。ママ→お姉さん→キャストの階層育成構造がある。同伴ペース管理（週2・月7回目標）を重視。
- **キャバクラ（cabaret）**: 指名制。指名化と来店頻度が鍵。

## 4つのロールと提供機能

### ① キャスト（ホステス本人）
- **連絡リスト（最重要）**: 「今日連絡すべき客」を AI が優先度付け（前回来店からの間隔、誕生日、指名化チャンス等の理由付き）。
- **顧客カルテ**: 氏名/源氏名/誕生日/職業/好きな酒/カテゴリ(VIP/常連/新規)/エリア/店舗共有メモ(閲覧専用)/個人メモ(編集可、前回話題・接客のコツ・次回話すこと)。
- **LINE スクショから記憶抽出**: 客との LINE 画像をアップ → Claude vision が要約・話題・接客メモを抽出 → カルテに反映。名刺撮影も同様。
- **来店履歴 / ボトル管理 / 紹介ツリー**: 誰がいつ来ていくら使ったか、キープボトルの残量、誰が誰を紹介したか（お連れ様ランキング）。
- **個人KPIダッシュボード**: 月間売上 vs 目標、指名本数、リピート率、新規数、年間累計、推移グラフ。
- **シフト/同伴スケジュール管理**: 出勤・同伴予約（予定/完了/キャンセル理由）・個人予定。
- **メッセージテンプレート**: お礼/誘い/誕生日/季節を、{姓}{前回の話題}{ボトル残量}等で差し込み生成。
- **チームチャット**: ママ/姉さんキャストとの1on1・グループ・QR連絡先交換。
- **さくらママ AI（下記）**。

### ② ママ / お姉さん（先輩キャスト・育成者）
- **チーム一覧 + 育成リマインダ**: 担当キャストの KPI バッジ、1on1 空き・目標未設定の優先カード。
- **キャスト別カルテ**: 個人成績・目標設定（売上/同伴）・1on1チャット。
- **同伴ペース監視**: キャスト別に週2/月7の達成度を信号（緑/黄/赤）で表示、キャンセル理由も把握。
- **全顧客ビュー + マップ**: 店の全顧客をエリアで可視化。
- さくらママ AI（キャストと同等）。

### ③ 店舗スタッフ / オーナー（入力と分析の主体）
- **顧客登録**: 氏名/カナ/源氏名/誕生日/職業/好きな酒/カテゴリ/エリア/店舗メモ/紹介元・紹介先。
- **来店登録**: 日付/客/卓/指名フラグ/売上金額。
- **ボトル管理**: 銘柄/総杯数/残杯数。
- **顧客一覧・来店履歴・ボトル**: 検索/フィルタ/CSVエクスポート。
- **キャスト宛メッセージ & 依頼キュー**: 連絡事項の一斉送信、キャストからの依頼処理。
- **クーポン発行**: ドリンク/誕生日/割引/VIP、有効期限・利用追跡。
- **承認キュー（オーナー）**: ヘルプキャストの顧客プロフィール変更提案を承認/却下。
- **同伴ペース・ダッシュボード（オーナー）**: 店全体、ママ/キャスト別、アラート状態。
- **顧客ファネル分析（オーナー）**: store_only（店だけが知る）→ assigned（担当付与）→ line_exchanged（LINE交換）の多段コンバージョン、キャスト別/カテゴリ別、直近 LINE 交換、紹介者ランキング。
- **効果ダッシュボード**: キャスト別売上、新規数、主要KPI、フォロー対象ヒートマップ。

### ④ 来店客（カスタマーアプリ）
- **キープボトル一覧・クーポンウォレット・店ごとの来店/利用サマリ**。
- **会員ランク**: bronze→silver→gold→platinum→diamond の5段階（来店回数ベース）、次ランクまでの進捗。

## さくらママ AI（中核の差別化要素）
- **30年選手のママ人格**: 温かいが鋭い、実務的、ジャッジしない。ナイトワークの商習慣（ピーク帯19-01時、LINE作法、指名の序列、ボトルキープ心理）を内蔵。
- **4つの相談意図**: フォロー（いつ何を送るか）/ 接客中（会話が止まった・ボトル提案のタイミング・VIP機嫌）/ 戦略（新規が伸びない・リピート低下・指名頭打ち）/ 自由相談。
- **マルチモーダル**: テキスト + 画像3枚まで（自撮りの身だしなみチェック、店内雰囲気、客とのLINEスクショ解析）。
- **3案ピッカー出力**: A=安全（保守的）/ B=実践（短く行動明確）/ C=温かい（情緒的）。各案に「具体的なLINE文面例（絵文字1-3個）」+「なぜ効くか（心理 + 商習慣の理由）」。
- **改良ループ**: 気に入らなければ「もっと丁寧に/温かく/パンチを」で3案再生成。helpful/not-helpful フィードバックで以後バイアス調整。
- **データ接続**: 顧客カルテ全項、直近来店間隔、全ボトル残量、店舗メモの制約（例「離婚調停中なので家庭の話題NG」）まで文脈に入れる。
- **コスト**: claude-haiku モデルで約 $0.005/回。API キー無しでもペルソナ準拠スタブで動く。

## 現状の課金実装状況（事実）
- 現状は **フリーミアムの骨組みのみ**。Stripe 未接続、課金フロー未実装、従量課金の項目も未確定。
- `BASE_PLAN_NAME="無料プラン"`、`PLAN_TAGLINE="基本無料・必要に応じて課金"`、`METERED_BILLING_READY=false`。
- つまり **マネタイズはこれから設計する** 段階。

## 発注者（あなたが助ける人）が現時点で持っているビジネスモデル仮説
1. **キャスト課金**: 1人あたりは少額。カード登録からの月額課金で離脱しにくい仕組みにする。
2. **店舗課金 (a)**: これまでできていなかった「キャスト→客」の部分の管理ができることで店の売上が上がる。
3. **店舗課金 (b)**: 上記で店の利益が増えるため、その分アプリに課金しても元が取れる（=バリューベース・プライシング）。

# あなたへの依頼：以下を Part 1〜4 の順で出力せよ

## Part 1. ミクロのバリュー評価 — 「誰に・どんな価値が・どれくらい」

ステークホルダー（キャスト / ママ / 店舗オーナー / 来店客 / 業界全体）ごとに、**推定の数値アウトカム**で価値を定量化する。一店舗・一キャストという**ミクロの単位**で組み立てること。

各ステークホルダーについて最低限：
- **解いている痛み（Job to be done）** を1-2行で。
- **数値アウトカムの推定**: 例「キャスト1人あたり、連絡リストとAI文面でフォロー実行率が X%→Y% に上がり、リピート率が +Z pt、指名が月 +N本、結果として月商が +¥M」。前提（客数・客単価・指名料・同伴単価・現状リピート率など）を明示し、楽観/基準/悲観の3点を出す。日本のキャバ/クラブの一般的な単価・指名料・同伴バックの相場は検索 or 妥当な推定で補い、根拠を示す。
- **その価値の「誰の財布」へのインパクトか**（キャスト個人の手取りか、店の粗利か）を必ず分離する。
- **アウトカムが立つ条件と、立たない条件（反証）** を併記。

最後に **「最も大きく・最も確実に金銭価値が立つのは誰か」ランキング** を理由付きで提示。

## Part 2. 支払意思額（WTP）と「誰が払うべきか」

- 各ステークホルダーの **WTP（月額・年額）** を、Part 1 で出した金銭価値の何%を回収できるかという観点で推定（バリューベース）。日本のナイトワークのキャストの平均月収レンジ、店の月商レンジも前提として置く。
- **課金主体の力学**を分析：キャストは出入りが激しく財布も別 / 店はキャストの私物ツール導入を嫌う or 歓迎するか / 「店が払ってキャストが使う」B2B2C と「キャスト個人課金」B2C のどちらが、解約・浸透・拡大の観点で優れるか。
- **発注者の3仮説を1つずつ批評**：それぞれの強み・致命的リスク・前提が崩れる条件・改善案。特に「キャスト個人課金 × カード登録で離脱防止」は、ナイトワークの高い離職率（在籍数ヶ月）と相性が良いか悪いかを論じる。

## Part 3. ビジネスモデルの決定提案（キャバクラ / クラブ で分けて）

業態の力学が違う（キャバ=指名制で個人商店性が強い / クラブ=担当制で店とママの統制が強い）ことを踏まえ、**業態別に**最適なモデルを設計：

- **課金構造**: 誰が・何に対し・いくら・どの粒度（店舗席数別 / キャスト人数シート課金 / AI従量 / 成果連動）で払うか。
- **パッケージング**: 無料で配る境界線（PLG のフック）と、有料の壁をどこに置くか。さくらママ AI を有料の主軸にするか、CRM を主軸にするか。
- **解約しにくい仕組み（モート）**: データ蓄積・乗り換えコスト・店ぐるみ導入・キャスト間ネットワーク効果のどれで作るか。離職してもデータと課金が店に残る設計の可否。
- **GTM（最初の100店をどう取るか）**: 営業経路（スカウト会社・ナイトワーク系メディア・代理店・横のつながり）、価格の見せ方、無料トライアル設計、初期の一押し機能。
- **ユニットエコノミクス試算**: 想定 ARPU、CAC、チャーン、回収期間、店舗あたり/キャストあたり LTV を、楽観/基準/悲観で表に。AI 原価（$0.005/回 × 想定利用回数）も粗利に織り込む。

最後に **「これで行く」という1つの推奨モデル**を、業態別に断定的に提示（迷ったら基準ケースで決め切る）。そう決める理由と、最初に潰すべきリスク仮説、最初の30日で回す検証実験を3つ挙げる。

## Part 4. その他の夜業態への市場参入余地

キャバ/クラブ以外の夜業態（**スナック・ラウンジ・ガールズバー・ホストクラブ・コンカフェ・メンズエステ/セラピスト系・ニュークラブ** 等）について：
- 各業態の **市場規模（店舗数・市場金額の推定、出典/推定の別を明記）**、商習慣の違い、NIGHTOS の機能適合度（そのまま使える / 改修が要る / 不向き）。
- **隣接性スコア**（既存プロダクトからの距離）と **参入魅力度**（規模 × 取りやすさ × 解約しにくさ）で2軸マッピング。
- **横展開の順序**：どの業態を2番目・3番目に攻めるべきか、理由付きのロードマップ。
- ホストクラブは客=女性・売掛文化・色恋営業で力学が逆である点など、**安易な転用が危険な業態の警告**も入れる。

# 出力ルール（厳守）

1. 構成は Part 1→4 の順。各 Part の冒頭に3行以内のエグゼクティブサマリ。
2. 数値は必ず **表 + 前提 + 楽観/基準/悲観** の形。単一の点推定で言い切らない。
3. 公開情報による根拠と、ロジック推定を **明確に区別**（「[推定]」「[要検証]」のタグを使う）。
4. 不確実なものを確実そうに書かない。わからないことは「これは検証が必要」と書く。
5. 最後に **「発注者が次の2週間で取るべき意思決定 TOP5」** を、決断の二択とあなたの推奨を添えて箇条書き。
6. 日本語で、日本市場・日本円・日本の商習慣前提で書く。

## 補足：このプロンプトの設計意図（発注者向けメモ）

- **「数値アウトカム・ミクロ視点」の要求**は Part 1 に集約。AI に相場（指名料・同伴バック・キャスト月収・店月商）を埋めさせつつ、前提と感度を強制することで「それっぽい一点予測」を防いでいる。
- **3つの自社仮説を名指しで批評させる**（Part 2）ことで、肯定だけの当たり障りない回答を回避。特に「キャスト個人課金 × カード離脱防止」は、ナイトワークの高離職率と真っ向から対立しうる論点なので、必ず突っ込ませる設計。
- **業態別（キャバ/クラブ）に分けて決め切らせる**（Part 3）。担当制 vs 指名制で「誰が払うのが自然か」が変わるため。
- **横展開（Part 4）にホスト等の逆力学の警告**を明示要求。安易な「全部いけます」を防ぐ。
- 出力ルールで **「次の2週間の意思決定TOP5」** を必須化し、分析を行動に落とす。
